# Спецификация бейзлайна

Согласовано 11 ноября 2026. Цель — локализация спектра, без второго этапа уточнения λ,
без новых антипиковых штрафов и без автоматических перезапусков.

## Постановки

| Задача | Уравнение | Пространственная область | λ | Активные границы |
|---|---|---|---|---|
| Laplace 1D | u_xx + λu = 0 | [0, π] | [0.5, 18] | u(0)=u(π)=0 |
| Laplace 2D | u_xx + u_yy + λu = 0 | [0, π]² | [0.5, 10] | u=0 на четырёх сторонах |
| Непрерывный спектр из теплопроводности | u_xx + λu = 0 | вычислительное окно [0, 5] | [-5, 5] | u(0)=0; справа условия нет |

1D Laplace восстановлен по `ARTICLE_MATERIALS.md`, раздел 3; отдельного исходного скрипта нет.
2D использует границы и диапазон из фактически вызываемого `laplace_2d/problem.py`.
`used_config.yaml` содержит [1,11], но прежний `run_train.py` не передавал эти параметры в функцию;
поэтому сохранены её действовавшие defaults [0.5,10]. Для смены диапазона есть Hydra overrides.
Непрерывный пример перенесён из `heat_1D_eigenvalues/problem.py`; это пространственная
спектральная задача после разделения переменных, без времени как входа.

Источники: существующие `heat_1D_eigenvalues`, `laplace_2d`, `ARTICLE_MATERIALS.md`, `ANALYSIS.md`.
Исходные каталоги не изменяются. Физическая постановка на полуоси интерпретируется только
в пределах существующего конечного окна; численная нормировка не доказывает ограниченность на бесконечности.

## Архитектура и обучение

Все задачи: MultiPINN PirateNet, `hidden_size=256`, `num_blocks=1`, `gamma=0.5`,
`nonlinearity=0.0` (явно записанное исходное значение по умолчанию).
Входы `(x,λ)` или `(x,y,λ)`, один скалярный выход. Float32.
Сиды **17,43,101,257,7919** применяются ко всем задачам; одно обучение на каждый сид.

| Задача | Точек на каждое внутреннее условие | На каждую активную границу | Эпох | Adam LR | ExponentialLR gamma |
|---|---:|---:|---:|---:|---:|
| Laplace 1D | 30000 | 5000 | 140000 | 1e-4 | 0.99997 |
| Laplace 2D | 100000 | 20000 | 100000 | 1e-4 | 1.0 |
| Непрерывный пример | 30000 | 5000 | 140000 | 1e-4 | 0.99997 |

Три внутренних условия имеют свои независимо сгенерированные выборки, как в исходном Generator.
Итого это три массива по указанному числу точек, а не трёхкратное уменьшение размера PDE-выборки.
`sampler=pseudo`, обновление каждые 1000 шагов. Один полный батч для глобальных mean/max.
Схема scheduler и число эпох 2D сохранены из его конфигурации; 1D использует настройки
непрерывного прототипа по согласованию пользователя.

## Потери

Для каждой задачи в её `problem.py` определены:

1. Остаток PDE r = Δu + λu.
2. Остаток нетривиальности B = 1 / (100 mean(u²) + 1).
3. Остаток нормировки abs(max(abs(u)) - 1).
4. Остаток u на каждой активной границе.

Среднее/максимум вычисляются по всей пространственно-спектральной выборке соответствующего
условия, не отдельно для каждого λ. MultiPINN возводит остатки в квадрат и усредняет.
Таким образом, компонентой нетривиальности служит **B²**, сохранена исходная семантика Condition.
Изменение коэффициентов в 2D на a=100,b=1 согласовано в обсуждении.

`AdaptiveConditions`, LR адаптивного optimizer `1e-4`, с согласованной локальной поправкой:
все K компонентов начинают с одинаковых весов 1/K (нулевые softmax-логиты), независимо
от количества точек. В 1D это 1/5, в 2D — 1/7, в непрерывном примере — 1/4.
Каждая активная граница остаётся отдельной компонентой. Используется локальный класс
`EqualInitialAdaptiveConditionsLosses` из `adaptive_conditions.py`; установленный MultiPINN
не изменяется. Дальнейшее обновление весов наследуется от MultiPINN без изменений.
Перегенерация точек не сбрасывает адаптивные веса. Конфиг фиксирует `initialization: equal`,
история весов логируется; отпечаток локальной реализации включается в `environment.json`.

## Артефакты и анализ

Каждая эпоха — CSV числовых лоссов и адаптивных весов. Каждые 1500 эпох и на последней —
checkpoint и NPZ независимой фиксированной оценки. Графики при обучении не строятся.
Checkpoints позволяют восстановить модель для дальнейшей оценки на более плотной сетке.
Единичная пиковая амплитуда используется только в постобработке; исходные значения сохраняются.

Сохраняются энергия, RMS, max|u|, абсолютные и относительные невязки PDE/границ по λ;
срезы с RMS/max ниже численных порогов помечаются невалидными для нормировки.
Заранее известные аналитические моды добавляются к оценочным λ исключительно для сравнения,
не используются для обучения или принудительного поиска кандидатов.

Скрипты строят все согласованные графики и сводку пяти сидов из сохранённых чисел.
Slurm-скрипт и решение о распределении GPU — следующий отдельный этап.

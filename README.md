# Спектральная задача

Бейзлайн локализации спектра одной параметризованной PirateNet, три задачи × пять сидов.
Сиды: **17, 43, 101, 257, 7919**. Обучение не рисует графики: сохраняет числа и checkpoints.

## Структура

```text
laplace_1d/       problem.py, train.py, config/config.yaml
laplace_2d/       problem.py, train.py, config/config.yaml
heat_continuous/  problem.py, train.py, config/config.yaml
artifact_tools.py # сохранение и независимая числовая диагностика
adaptive_conditions.py # AdaptiveConditions с равными начальными весами
evaluate.py       # повторная оценка выбранного checkpoint
plot.py           # отрисовка только из CSV/NPZ
SPECIFICATION.md  # согласованные постановки, потери и параметры
```

В каждой задаче свои `problem.py`, `train.py` и конфиг. Общего `src` нет.
Корневые инструменты обслуживают только артефакты и анализ.

## Адаптивные веса

Во всех трёх задачах `AdaptiveConditions` начинает с одинаковых весов компонентов:
1/5 для Laplace 1D, 1/7 для Laplace 2D и 1/4 для непрерывного примера.
Локальный `adaptive_conditions.py` меняет только инициализацию, убирая зависимость
начального веса от числа остатков. Последующее обучение весов остаётся штатным;
перегенерация точек их не сбрасывает. Это явно записано как `initialization: equal`
в конфиге, а SHA256 локального класса сохраняется в `environment.json`.

## Запуск

Один сид:

```bash
python laplace_1d/train.py trainer.random_seed=17
python laplace_2d/train.py trainer.random_seed=17
python heat_continuous/train.py trainer.random_seed=17
```

Пять фиксированных сидов через штатный последовательный Hydra multirun:

```bash
python laplace_1d/train.py --multirun
python laplace_2d/train.py --multirun
python heat_continuous/train.py --multirun
```

Быстрая проверка без полного эксперимента:

```bash
python laplace_1d/train.py trainer.device=cpu trainer.num_epochs=3 \
  generator.domain_points=32 generator.boundary_points_per_condition=8 \
  model.params.hidden_size=16 artifacts.save_period=2 \
  evaluation.lambda_points=5 evaluation.spatial_points_per_axis=7
```

## Артефакты каждого запуска

- `used_config.yaml` — разрешённая конфигурация.
- `environment.json` — версии и отпечатки реализации зависимостей.
- `metrics.csv` — каждая эпоха: время, LR после scheduler, общий взвешенный лосс,
  невзвешенные компоненты и адаптивные веса.
- `checkpoints/epoch_0001500.pth` — state dict модели, optimizer/scheduler, адаптивные
  параметры и optimizer, состояния RNG и текущие коллокационные точки.
- `predictions/epoch_0001500.npz` — фиксированная независимая сетка, исходные поля,
  поля с единичным максимумом, энергия, RMS, максимум, невязки и аналитические эталоны.

Checkpoint и NPZ сохраняются каждые 1500 эпох и на последней эпохе.
История лоссов относится к вычислению до обновления модели, а checkpoint/predictions —
к модели после этого шага. Команда автоматического продолжения обучения пока не реализована;
checkpoints поддерживают загрузку для анализа.

Коллокационные точки перегенерируются после каждых 1000 шагов. Один полный батч сохраняет
смысл среднего и максимума по всей выборке. Уменьшать память простым увеличением числа батчей
нельзя: это изменит глобальные штрафы. Размер чанка при **оценке** менять можно.

## Повторная оценка и отрисовка

```bash
python evaluate.py /path/to/run/checkpoints/epoch_0001500.pth \
  --output /path/to/run/predictions/dense.npz --spatial-points 101 --lambda-points 401
python plot.py /path/to/run --format pdf
python plot.py /path/to/run --epoch 1500 --format svg
```

`plot.py` по умолчанию берёт последний `epoch_*.npz`. Чтобы нарисовать произвольный NPZ,
используйте `--predictions /path/to/run/predictions/dense.npz` для одного запуска.
Для объединения пяти сидов одной задачи передайте пять каталогов:

```bash
python plot.py /path/to/seed17/run /path/to/seed43/run /path/to/seed101/run \
  /path/to/seed257/run /path/to/seed7919/run --summary-dir figures/laplace_1d
```

Сохраняются истории лоссов и весов, спектральные диагностические кривые, исходные и
нормированные функции, эталонные моды, 2D heatmaps и карта непрерывного примера.
Для нескольких сидов сохраняются также числовой `seed_summary.npz`, среднее и стандартное
отклонение общего тренировочного лосса. Лоссы с разными адаптивными весами не заменяют
сравнение независимых невязок и предсказаний.

## Смысл нормировки и диагностики

`raw` — исходный ответ сети. `unit_peak = raw / max(abs(raw))` вычисляется отдельно для каждого λ
и только при достаточных RMS и максимуме. Это единичный максимум **на оценочной сетке**,
а не доказанный максимум на непрерывной области. Нормировка не меняет тренировочный лосс,
форму, знак или качество решения. Пороговые `min_rms=min_peak=1e-6` являются настраиваемой
численной отсечкой; они не доказывают нахождение собственной функции.

При почти нулевом срезе `valid=False`, нормированное поле и относительные невязки равны `NaN`.
Энергия и PDE MSE считаются на внутренних узлах; граничные MSE — отдельно на каждой активной
границе. Относительные невязки делятся на энергию среза без маскирующего ε.

Срезовые `normalization_loss` и `nontriviality_loss` — диагностические величины,
а не компоненты фактического глобального тренировочного лосса. Их сумма на графике
не использует обученные веса и не выдаётся за тренировочный loss.

Для Laplace аналитические моды перечисляются отдельно; при вырожденном λ сеть может
выдать их линейную комбинацию. Сравнение с одной базисной модой не определяет ошибку
собственного подпространства. Для непрерывного примера отрицательная область эталона
доопределена нулём, как в исходниках.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Проверки используют аналитические функции для контроля знака PDE, независимости
относительной невязки от амплитуды и обработки нулевого поля. Также проверяются равные
начальные веса, независимость от количества точек и сохранение адаптации при обновлении
выборки. Полное обучение в них не запускается.
